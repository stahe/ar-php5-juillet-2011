    10. خوادم في PHP

    نظرًا لأن البرامج PHP يمكن تنفيذها بواسطة خادم WEB، فإن مثل هذا البرنامج يصبح برنامج خادم قادرًا على خدمة عدة عملاء. من وجهة نظر العميل، فإن استدعاء خدمة WEB يعادل طلب URL لهذه الخدمة. يمكن كتابة العميل بأي لغة، لا سيما بلغة PHP. في هذه الحالة الأخيرة، يتم استخدام وظائف الشبكة التي رأيناها للتو. كما يتعين علينا أن نعرف كيفية "التواصل" مع خدمة WEB، أي فهم بروتوكول http للاتصال بين خادم الويب وعملائه. وهذا هو الهدف من البرامج التالية.

    وقد سمح لنا عميل الويب الموصوف في الفقرة 9.2 باكتشاف جزء من بروتوكول HTTP.

    في أبسط صورها، تتم عمليات التبادل بين العميل والخادم على النحو التالي:

    • يقوم العميل بفتح اتصال مع المنفذ 80 لخادم الويب
    • يُرسل طلبًا بشأن مستند ما
    • يرسل خادم الويب المستند المطلوب ويغلق الاتصال
    • يقوم العميل بدوره بإغلاق الاتصال

    يمكن أن يكون العميل من أنواع متنوعة: نص بتنسيق HTML، أو صورة، أو مقطع فيديو، ... وقد يكون مستندًا موجودًا (مستند ثابت) أو مستندًا يتم إنشاؤه على الفور بواسطة برنامج نصي (مستند ديناميكي). في الحالة الأخيرة، نُطلق على ذلك اسم برمجة الويب. يمكن كتابة البرنامج النصي لتوليد المستندات ديناميكيًا بعدة لغات: PHP، Python، Perl، Java، Ruby، C#، VB.net، ...

    نستخدم هنا PHP لإنشاء مستندات نصية ديناميكيًا.

    • في [1]، يقوم العميل بفتح اتصال مع الخادم، ويطلب برنامجًا نصيًّا PHP، ويرسل أو لا يرسل معلمات إلى هذا البرنامج النصي
    • في [2]، يقوم خادم الويب بتشغيل البرنامج النصي PHP بواسطة مترجم PHP. ويقوم هذا البرنامج النصي بإنشاء مستند يتم إرساله إلى العميل [3]
    • يقوم الخادم بإنهاء الاتصال. ويقوم العميل بالمثل.

    يمكن لخادم الويب معالجة عدة عملاء في وقت واحد. مع حزمة البرامج WampServer، يكون خادم الويب هو خادم Apache، وهو خادم مفتوح المصدر من مؤسسة Apache (http://www.apache.org/). في التطبيقات التالية، يجب تشغيل WampServer. يؤدي ذلك إلى تنشيط ثلاثة برامج: خادم الويب Apache، و SGBD MySQL، ومترجم PHP.

    سيتم كتابة البرامج النصية التي ينفذها خادم الويب باستخدام أداة Netbeans. وقد كتبنا حتى الآن برامج نصية PHP تُنفذ في سياق وحدة التحكم:

    يستخدم المستخدم وحدة التحكم لطلب تنفيذ البرنامج النصي PHP والحصول على نتائجه.

    في تطبيقات العميل/الخادم التالية،

    • يتم تنفيذ البرنامج النصي للعميل في سياق وحدة التحكم
    • يتم تنفيذ البرنامج النصي الخاص بالخادم في سياق الويب

    لا يمكن أن يكون البرنامج النصي PHP الخاص بالخادم موجودًا في أي مكان في نظام الملفات. في الواقع، يبحث خادم الويب في المواقع المحددة في التكوين عن المستندات الثابتة والديناميكية المطلوبة منه. تؤدي الإعدادات الافتراضية لـ WampServer إلى البحث عن المستندات في المجلد <WampServer>/www، حيث يمثل <WampServer> مجلد تثبيت WampServer. وبالتالي، إذا طلب عميل الويب مستند D باستخدام URL [http://localhost/D]، فسيقوم خادم الويب بتقديم المستند D الموجود في المسار [<WampServer>/www/D].

    في الأمثلة التالية، سنضع نصوص الخادم في المجلد [www/exemples-web]. إذا كان اسم نص الخادم هو S.php، فسيُطلب من خادم الويب باستخدام URL و [http://localhost/exemples-web/S.php]. سيتم عندئذ تقديم المستند [<WampServer>/www/exemples-web/S.php] إليه.

    بعد ذلك، سنواجه نوعين من عملاء الويب:

    • متصفح مثل المذكور أعلاه. وقد ذكرنا أن خادم الويب يرسل استجابة على النحو التالي: رؤوس HTTP، سطر فارغ، نص. لا يعرض المتصفح سوى texte.

    10.1. تطبيق العميل/الخادم للتاريخ/الوقت

    10.1.1. الخادم (web_01)

    
<?php
// الوقت: عدد المللي ثانية منذ 01/01/1970
// تنسيق عرض التاريخ والوقت
// d: اليوم برقمين
// m: الشهر برقمين
// y: السنة برقمين
// H: الساعة 0,23
// i: الدقائق
// s: الثواني
print date("d/m/y H:i:s",time());

    بشكل أساسي، يقوم البرنامج النصي PHP أعلاه بكتابة الوقت الحالي على الشاشة. ومع ذلك، عند تنفيذه بواسطة خادم ويب، يتم إعادة توجيه الدفق رقم 1 الذي يرتبط عادةً بالشاشة إلى الاتصال الذي يربط الخادم بعميله. لذلك، في سياق الويب، يرسل البرنامج النصي أعلاه الوقت الحالي في شكل نص إلى العميل.

    لنقم بتشغيل هذا البرنامج النصي داخل NetBeans:

    • في [1]، يتم تنفيذ البرنامج النصي. ثم يتم تشغيل متصفح ويب.
    • في [2]، يتم طلب URL من قبل متصفح الويب
    • في [3]، النص المرسل بواسطة البرنامج النصي للخادم

    يستخدم متصفح العميل بروتوكول HTTP للتواصل مع خادم الويب. وقد سبق أن وصفنا شكل هذا البروتوكول.

    يرسل العميل أسطر نصية يمكن تقسيمها إلى ثلاثة أجزاء: رؤوس HTTP، سطر فارغ، مستند. غالبًا ما يكون المستند المرسل إلى خادم الويب فارغًا أو عبارة عن مجموعة من المعلمات parami=vali حيث vali هي قيمة أدخلها المستخدم في نموذج HTML.

    تتخذ استجابة الخادم الشكل نفسه: رؤوس HTTP، سطر فارغ، مستند، حيث يمثل document هذه المرة المستند المطلوب من قبل متصفح العميل. إذا أرسل العميل معلمات، فإن المستند المرسَل يعتمد عمومًا على هذه المعلمات.

    10.1.2. عميل (client1_web_01)

    نقوم الآن بكتابة برنامج نصي للعميل للخدمة السابقة. نعلم أن على العميل:

    • فتح اتصال مع خادم الويب
    • إرسال النص: رؤوس HTTP، سطر فارغ
    • قراءة الرد الكامل من الخادم حتى يقوم هذا الأخير بإغلاق اتصاله مع العميل
    • إغلاق الاتصال بالخادم

    يتم تنفيذ البرنامج النصي للعميل في بيئة وحدة التحكم في NetBeans:

    • في [1]، يتم تضمين البرنامج النصي للعميل [client1_web_01.php] في مشروع Netbeans [exemples]
    • في [2]، خصائص مشروع NetBeans [exemples]
    • في [3]، يتم تشغيل مشروع NetBeans [exemples] في وضع «سطر الأوامر»، وهو ما أطلقنا عليه أيضًا اسم وضع «وحدة التحكم».

    رمز البرنامج النصي للعميل هو التالي:

    
<?php

// البيانات
$HOTE = "localhost";
$PORT = 80;
$urlServeur = "/exemples-web/web_01.php";
// فتح اتصال على المنفذ 80 لـ $HOTE
$connexion = fsockopen($HOTE, $PORT);
// خطأ؟
if (!$connexion) {
  print "Erreur : $erreur\n";
  exit;
}
// يجب أن تنتهي رؤوس (headers) بروتوكول HTTP بسطر فارغ
// GET
fputs($connexion, "GET $urlServeur HTTP/1.1\n");
// المضيف
fputs($connexion, "Host: localhost\n");
// الاتصال
fputs($connexion,"Connection: close\n");
// سطر فارغ
fputs($connexion,"\n");
// سيقوم الخادم الآن بالرد على القناة $connexion. سيقوم بإرسال جميع
// بياناته ثم يغلق القناة. وبالتالي يقرأ العميل كل ما يصل من $connexion
// حتى إغلاق القناة
while ($ligne = fgets($connexion, 1000)) {
  print "$ligne";
}//بينما
// يقوم العميل بدوره بإغلاق الاتصال
fclose($connexion);
// النهاية
exit;

    10.2. استرداد الخادم للمعلمات المرسلة من العميل

    في بروتوكول HTTP، يتوفر للعميل طريقتان لتمرير المعلمات إلى خادم الويب:

    • يطلب URL من الخدمة بالشكل 
    
GET url?param1=val1&param2=val2&param3=val3… HTTP/1.0

    حيث يجب أن تخضع قيم vali مسبقًا لعملية ترميز بحيث يتم استبدال بعض الأحرف المحجوزة بقيمتها السداسية العشرية.

    • يطلب URL من الخدمة بالصيغة 
    
POST url HTTP/1.0

    ثم يضع الرأس التالي ضمن الرؤوس HTTP المرسلة إلى الخادم:

    Content-length=N

    تنتهي سلسلة الرؤوس المرسلة من قبل العميل بسطر فارغ. يمكنه بعد ذلك إرسال بياناته بالشكل

    val1&param2=val2&param3=val3…

    • $_GET["parami"] لأمر GET
    • $_POST["parami"] لأمر POST

    10.4. إدارة الجلسات WEB

    في أمثلة العميل/الخادم السابقة، كان العمل يسير على النحو التالي:

    • يقوم العميل بفتح اتصال بالمنفذ 80 لجهاز خدمة الويب
    • يرسل تسلسل النص: رؤوس Http، سطر فارغ، [document]
    • رداً على ذلك، يرسل الخادم تسلسلاً من نفس النوع
    • يغلق الخادم الاتصال مع العميل
    • يقوم العميل بإغلاق الاتصال بالخادم

    إذا أرسل نفس العميل طلبًا جديدًا إلى خادم الويب بعد ذلك بوقت قصير، يتم إنشاء اتصال جديد بين العميل والخادم. ولا يمكن للخادم معرفة ما إذا كان العميل الذي يتصل قد زاره من قبل أم أن هذا هو الطلب الأول. بين اتصالين، «ينسى» الخادم عميله. ولهذا السبب، يُقال إن بروتوكول HTTP هو بروتوكول عديم الحالة. ومع ذلك، من المفيد أن يتذكر الخادم عملائه. فعلى سبيل المثال، إذا كان التطبيق آمنًا، سيرسل العميل إلى الخادم اسم مستخدم وكلمة مرور للتعريف بنفسه. وإذا "نسي" الخادم عميله بين اتصالين، فسيضطر العميل إلى التعريف بنفسه عند كل اتصال جديد، وهو أمر غير مقبول.

    ولمتابعة العميل، يتصرف الخادم على النحو التالي: عند تلقي الطلب الأول من العميل، يضمّن الخادم في رده معرّفًا يجب على العميل إرساله مرة أخرى في كل طلب جديد. وبفضل هذا المعرّف، الذي يختلف من عميل لآخر، يمكن للخادم التعرف على العميل. ويمكنه عندئذٍ إدارة ذاكرة خاصة بهذا العميل على شكل ملف مرتبط بشكل فريد بمعرّف العميل.

    من الناحية التقنية، يحدث الأمر على النحو التالي:

    • في الرد الموجه إلى عميل جديد، يضمّن الخادم الرأس HTTP Set-Cookie: MotClé=المعرّف. ولا يقوم بذلك إلا عند الطلب الأول.
    • في الطلبات التالية، سيقوم العميل بإرسال معرّفه عبر رأس الرسالة HTTP، مع ملف تعريف الارتباط: MotClé=المعرّف، حتى يتعرف عليه الخادم.

    قد يتساءل المرء كيف يعرف الخادم أنه يتعامل مع عميل جديد وليس مع عميل سبق له الزيارة. إن وجود الرأس HTTP Cookie في رؤوس HTTP الخاصة بالعميل هو ما يشير إلى ذلك. أما بالنسبة للعميل الجديد، فإن هذا الرأس يكون غائبًا.

    يُطلق على مجموعة الاتصالات الخاصة بعميل معين اسم "جلسة".

    10.4.3. العميل 1 (client1_web_05)

    نقوم الآن بكتابة برنامج نصي للعميل مستندًا إلى البرنامج النصي للخادم السابق. في إدارة الجلسة، يجب أن يتصرف مثل متصفح الويب:

    • في رد الخادم على طلبه الأول، يجب أن يعثر على معرّف الجلسة الذي يرسله إليه الخادم. وهو يعلم أنه سيجده في الرأس HTTP Set-Cookie.
    • يجب عليه، في كل طلب لاحق، أن يعيد إرسال المعرف الذي تلقّاه إلى الخادم. وسيقوم بذلك باستخدام الرأس HTTP Cookie.

    رمز العميل هو كما يلي:

    
<?php

// البيانات
$HOTE = "localhost";
$PORT = 80;
$urlServeur = "/exemples-web/web_05.php";
// اختبارات
$cookie = "";
for ($i = 0; $i < 5; $i++) {
  list($erreur, $cookie, $N1, $N2, $N3) = connecte($HOTE, $PORT, $urlServeur, $cookie);
  print "----------------------------\n";
  print "client(erreur,cookie,N1,N2,N3)=[$erreur,$cookie,$N1,$N2,$N3]\n";
  print "----------------------------\n";

function connecte($HOTE, $PORT, $urlServeur, $cookie) {
  // توصيل العميل بـ ($HOTE،$PORT،$urlServeur)
  // يرسل ملف تعريف الارتباط $cookie إذا كان غير فارغ
  // يعرض جميع الأسطر المستلمة كرد
  // فتح اتصال على المنفذ 80 لـ $HOTE
  $connexion = fsockopen($HOTE, $PORT);
  // خطأ؟
  if (!$connexion)
    return array("erreur lors de la connexion au serveur ($HOTE, $PORT)");
  // يتم الاتصال بـ $urlserveur
  // يجب أن تنتهي رؤوس (headers) بروتوكول HTTP بسطر فارغ
  // GET
  fputs($connexion, "GET $urlServeur HTTP/1.1\n");
  // المضيف
  fputs($connexion, "Host: localhost\n");
  // تسجيل الدخول
  fputs($connexion, "Connection: close\n");
  // يتم إرسال ملف تعريف الارتباط إذا لم يكن فارغًا
  if ($cookie) {
    fputs($connexion, "Cookie: $cookie\n");
  }//if
  // إرسال سطر فارغ
  fputs($connexion, "\n");
  // يتم عرض استجابة خادم الويب
  // ونحرص على استرداد ملف تعريف الارتباط (إن وجد) وقيم Ni
  $N = "";
  while ($ligne = fgets($connexion, 1000)) {
    print "$ligne";
    // ملف تعريف الارتباط - فقط عند الرد الأول
    if (!$cookie) {
      if (preg_match("/^Set-Cookie: (.*?)\s*$/", $ligne, $champs)) {
        $cookie = $champs[1];
      }
    }
    // قيمة N1
    if (preg_match("/^N1=(.*?)\s*$/", $ligne, $champs))
      $N1 = $champs[1];
    // قيمة N2
    if (preg_match("/^N2=(.*?)\s*$/", $ligne, $champs))
      $N2 = $champs[1];
    // قيمة ملف تعريف الارتباط N3
    if (preg_match("/^N3=(.*?)\s*$/", $ligne, $champs))
      $N3 = $champs[1];
  }//بينما
  // يتم إغلاق الاتصال
  fclose($connexion);
  // العودة
  return array("", $cookie, $N1, $N2, $N3);
}

function connecte($HOTE, $PORT, $urlServeur, &$cookie) {
  // توصيل العميل بـ ($HOTE، $PORT، $urlServeur)
  // يرسل ملف تعريف الارتباط $cookie إذا كان غير فارغ
  // يعرض جميع الأسطر المستلمة كرد
  // يتم تمرير ملف تعريف الارتباط كمرجع ليتم مشاركته بين
  // البرنامج المستدعى والبرنامج المستدعي
  // فتح اتصال على المنفذ $PORT التابع لـ $HOTE
  $connexion = fsockopen($HOTE, $PORT);
  // خطأ؟
  if (!$connexion)
    return array("erreur lors de la connexion au serveur ($HOTE, $PORT)");
  // يجب أن تنتهي رؤوس (headers) بروتوكول HTTP بسطر فارغ
  // GET
  fputs($connexion, "GET $urlServeur HTTP/1.1\n");
  // المضيف
  fputs($connexion, "Host: localhost\n");
  // الاتصال
  fputs($connexion, "Connection: close\n");
  // يتم إرسال ملف تعريف الارتباط إذا لم يكن فارغًا
  if ($cookie) {
    fputs($connexion, "Cookie: $cookie\n");
  }
  // إرسال سطر فارغ
  fputs($connexion, "\n");
  // يتم عرض استجابة خادم الويب
  // ونحرص على استرداد ملف تعريف الارتباط إن وجد
  while ($ligne = fgets($connexion, 1000)) {
    print "$ligne";
    // ملف تعريف الارتباط - فقط عند الرد الأول
    if (!$cookie) {
      if (preg_match("/^Set-Cookie: (.*?)\s*$/", $ligne, $champs)) {
        $cookie = $champs[1];
      }
    }
  }
  // يتم إغلاق الاتصال
  fclose($connexion);
  // العودة
  return "";
}

class Personne {

// سمات الفئة
  private $prénom;
  private $nom;
  private $âge;

// أدوات الاسترجاع والتعيين

    return $this->prénom;

    return $this->nom;

    return $this->âge;
